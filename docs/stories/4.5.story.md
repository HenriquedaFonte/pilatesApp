# Story 4.5 — Envio pelo servidor

**Epic:** 4 — Mensagens para os alunos (PRD-003)
**Status:** Draft
**Estimativa:** M–L (6–8h)
**Tipo:** Edge Function + UI
**Esforço:** **dev-critico** (Edge Function, envio de emails)
**Depende de:** Stories 4.3 e 4.4

---

## User Story

**Como** professora,
**Quero** clicar em enviar e poder fechar a página,
**Para que** um envio para 100 alunos não pare no meio se o celular bloquear ou a internet cair.

---

## Acceptance Criteria

- [ ] **AC-1:** Edge Function nova (ex.: `send-campaign`) recebe só o `campaign_id`; confere que quem chama é staff; monta cada email no servidor a partir da campanha (texto por língua, variáveis, escape) e manda pelo Resend respeitando o limite de envio (pausa entre lotes).
- [ ] **AC-2:** Destinatários resolvidos no servidor a partir do filtro gravado (ou lista de ids gravada na criação), sempre só alunos; nunca endereço livre vindo do navegador.
- [ ] **AC-3:** Status de cada email gravado em `email_notifications` e contadores na campanha; se a função parar no meio, chamar de novo continua de onde parou (não manda duas vezes para quem já recebeu).
- [ ] **AC-4:** A tela mostra o progresso lendo a campanha (atualiza a cada poucos segundos) e permite sair da página.
- [ ] **AC-5:** Logs sem email, nome ou conteúdo (só ids e contagens). Erro do Resend não volta cru para o navegador.
- [ ] **AC-6:** Termo de consentimento (anexo PDF) continua funcionando (pelo servidor ou pelo caminho atual, decidir na story).
- [ ] **AC-7:** Testes das regras (permissão, retomada, escape) como em `src/tests/sendEmailPolicy.test.js`.
